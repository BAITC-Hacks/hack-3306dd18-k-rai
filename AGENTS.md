# Фронтенд «Граф денег» — бриф для Codex

Ты делаешь фронтенд хакатонного проекта. Времени мало (около 4 часов), поэтому работай этапами: после каждого этапа приложение должно собираться и работать. Не начинай следующий этап, пока текущий не проходит проверки.

Полное ТЗ кейса лежит в `docs/TZ_graf_deneg.md` (от корня репозитория). Прочитай разделы 3, 5, 7 и 9, остальное по необходимости.

## Что за проект

AML-аналитику банка правоохранительные органы передали список из 81 клиента, связанных с незаконным оборотом наркотиков (это «seed», нижний уровень цепочки). Банк выгрузил исходящие переводы этих клиентов на 4 колена вглубь: 2 248 узлов, 3 119 рёбер. Бэкенд уже присваивает каждому узлу роль (консолидатор, транзит, распределитель и так далее), кластер и приоритет.

Задача фронта: показать аналитику эту сеть так, чтобы он за минуты понял, кого проверять первым и почему. Это главный экран демо перед жюри, поэтому он должен быть зрелищным, но прежде всего понятным и надёжным.

Термины:
- узел — клиент банка (gid), ребро — агрегированные переводы от одного клиента другому;
- колено (`depth`) — сколько переводов отделяет узел от seed: 0 у seed, дальше 1–4;
- обрыв (`is_cutoff`) — узел на 4-м колене без исходящих. Это артефакт выгрузки, а не «деньги осели». Такой узел нельзя показывать как конечного получателя.

## Твоя зона

Работаешь только в папке `frontend/`. Бэкенд (`backend/`, пайплайн на Python) не трогай — его делают другие люди параллельно. Всё, что нужно от бэка, описано ниже в контракте.

## Стек и правила

- Next.js (App Router, последняя стабильная), TypeScript, Tailwind. Создавай проект неинтерактивными флагами.
- Граф: `react-force-graph-2d` (canvas, выдерживает 2–3 тысячи узлов).
- Статический экспорт: в `next.config` поставь `output: 'export'` и `images: { unoptimized: true }`. Сборка кладёт всё в `frontend/out`, бэкенд раздаёт эту папку, и проект живёт по одной ссылке. Поэтому никаких серверных фич Next: ни API routes, ни server actions, ни динамического SSR. Всё — клиентские компоненты.
- `react-force-graph-2d` обращается к `window`, поэтому на сервере он падает. Правильный паттерн: создай обёртку `components/GraphCanvas.tsx`, которая импортирует `ForceGraph2D` обычным импортом и держит `useRef` внутри себя, а на странице подключай саму обёртку через `dynamic(() => import('@/components/GraphCanvas'), { ssr: false })`. Не передавай ref через `dynamic` напрямую — он теряется. Наружу обёртка отдаёт методы (`focusNode`, `zoomToNodes`, `zoomToFit`) через `useImperativeHandle`.
- Переменные окружения:
  - `NEXT_PUBLIC_USE_MOCKS=true|false` — работать на моках или на реальном API;
  - `NEXT_PUBLIC_API_URL` — база API, пусто означает тот же origin.
- Проверка работы: `npm run build` и `npx tsc --noEmit`. **Никогда не запускай `npm run dev` как проверку** — он не завершается и повесит тебя до таймаута.
- Шрифт: Golos Text (кириллица) через пакет `@fontsource/golos-text`. Если пакет недоступен — `next/font/google` с `subsets: ['cyrillic', 'latin']`. Если сборка без интернета падает на шрифте — системный стек, это не блокер.
- Весь интерфейс на русском.

## Контракт данных

Положи эти типы в `lib/types.ts`. Все данные от бэка сначала проходят через `lib/normalize.ts`: он проверяет поля и подставляет безопасные значения по умолчанию, чтобы переименованное или отсутствующее поле не роняло интерфейс.

```ts
export type Role =
  | 'consolidator' | 'coordinator' | 'distributor'
  | 'transit' | 'terminal' | 'peripheral';

export interface GraphNode {
  id: number;              // gid
  role: Role;
  role_score: number;      // 0..1, уверенность в роли
  cluster_id: number;
  priority_score: number;  // 0..1
  depth: number;           // 0 = seed-уровень, 1..4 — колено
  is_seed: boolean;
  in_senders: number;      // уникальных отправителей
  out_receivers: number;   // уникальных получателей
  sum_in: number;          // ₸
  sum_out: number;         // ₸
  is_cutoff: boolean;      // обрыв выгрузки на 4-м колене
  evidence: string;        // почему такая роль, до 200 символов
}

export interface GraphLink {
  source: number;          // gid отправителя
  target: number;          // gid получателя
  sum_kzt: number;
  n_tx: number;
}

export interface Cluster {
  cluster_id: number;
  n_nodes: number;
  n_seed: number;
  sum_kzt_internal: number;
  top_gids: number[];
  hypothesis: string;
}

export interface TopItem {
  rank: number;
  gid: number;
  role: Role;
  priority_score: number;
  why: string;
}

export interface GraphData {
  nodes: GraphNode[];
  links: GraphLink[];
  clusters: Cluster[];
  top: TopItem[];
}

export interface AskRequest {
  question: string;
  selected_gids?: number[];  // узлы, выделенные пользователем
}

export interface AgentStep {
  tool: string;
  args: Record<string, unknown>;
  summary: string;
}

export interface AskResponse {
  answer: string;
  steps: AgentStep[];
  highlight_gids: number[];
  error?: string;
}
```

## API

От бэка нужны только два эндпоинта:

```
GET  {API}/api/graph   → GraphData
POST {API}/api/ask     → AskRequest → AskResponse
```

Всё остальное считаешь сам на клиенте: соседей узла, статистику, устойчивость сети. Для запросов к агенту используй `AbortController` с таймаутом 45 секунд.

## Режим моков

При `NEXT_PUBLIC_USE_MOCKS=true` данные берутся из `lib/mock.ts`. Генератор детерминированный (seeded PRNG, например mulberry32 с seed 42), чтобы при перезагрузке граф был тем же. Он должен быть похож на реальные данные по структуре:

- около 400 узлов: ~30 seed (часть без исходящих), дальше колена 1–4;
- 3 консолидатора с 8–15 разными отправителями;
- 2 распределителя с 25–40 получателями;
- цепочки транзитов и 1 координатор, куда стекаются деньги из цепочек 3+ разных seed;
- все узлы 4-го колена без исходящих, с `is_cutoff: true`;
- 5–6 кластеров, топ-20 по `priority_score`, осмысленные `evidence` и `why` с цифрами.

Мок агента (`mockAsk`) через 1,5 секунды возвращает 3–4 правдоподобных шага, ответ и `highlight_gids` (консолидатор и его отправители).

## Этапы

### Этап 1. Каркас и граф на моках
- Проект создан, моки генерируются, граф рисуется.
- Цвет узла по роли, стрелки показывают направление (`linkDirectionalArrowLength`).
- Размер узла: `3 + priority_score * 7`.
- Узлы рисуй через `nodeCanvasObject`: seed — со светлой обводкой, `is_cutoff` — пунктирный контур и прозрачность 35%.
- Легенда ролей и счётчики: узлов, рёбер, общий оборот, число узлов с обрывом. Всё считается из данных.

Готово, когда: `npm run build` проходит, граф виден, цвета и легенда совпадают.

### Этап 2. Поиск, карточка, приоритеты (обязательная часть ТЗ)
Это главное требование ТЗ: на защите жюри называет gid, и команда должна найти его на схеме и показать его связи.
- Поиск по gid: Enter → камера плавно наезжает на узел (`centerAt` + `zoom`, 800 мс), узел выбран, его входящие и исходящие связи подсвечены, остальное приглушено. Если узел скрыт фильтром, сначала показать всё. Если gid нет в данных — сообщение «Узла 12345 нет в графе».
- Вкладка «Узел»: gid, роль по-русски, уверенность в процентах, колено, кластер, отметки «seed» и «обрыв выгрузки», цифры (отправителей, получателей, пришло, ушло, доля пропуска), `evidence`. Ниже списки «Кто платил» и «Кому платил» (до 10 по сумме), клик по строке переходит к этому узлу. Для узла с обрывом — пояснение: «Выгрузка обрывается на 4-м колене: куда деньги ушли дальше, неизвестно. Узел не считается конечным получателем».
- Вкладка «Приоритеты»: топ-20 (ранг, gid, роль, полоска `priority_score`, `why` в две строки). Клик → фокус на узле. Над списком фильтр по роли.
- Кнопка «Спросить агента» в карточке открывает вкладку «Агент» с подставленным вопросом про этот узел.

Готово, когда: любой gid из данных находится за секунду, связи видны, карточка заполнена.

### Этап 3. Сцена «Расследовать»
- Стартовое состояние: видны только seed-узлы и подсказка «81 клиент из запроса правоохранительных органов. Нажмите «Расследовать»» (число бери из данных).
- «Расследовать»: каждые 1,2 секунды открывается следующее колено (фильтр по `depth`), в конце `zoomToFit(600, 60)` и открывается вкладка «Приоритеты».
- **Важно:** фильтруй исходные массивы узлов и рёбер, не создавай новые объекты узлов. Иначе координаты сбросятся и граф будет прыгать. Рёбра показывай, только если оба конца видимы.
- Частицы по рёбрам (`linkDirectionalParticles`) только на подсвеченных рёбрах или рёбрах выбранного узла, иначе на 3 тысячах рёбер всё будет тормозить. Скорость частиц можно привязать к сумме.

### Этап 4. Агент
- Вкладка «Агент»: поле вопроса, кнопки-подсказки («Кто собирает деньги с выбранных узлов?», «Какой кластер выглядит опаснее всего и почему?», «Куда уходят деньги от узла {gid}?»).
- Shift+клик по узлам добавляет их в выделение. Выбранные gid показаны чипами и уходят в `selected_gids`.
- Пока агент думает: «Агент исследует граф…». После ответа — шаги понятными фразами (`get_node` → «Изучил узел», `get_senders` → «Посмотрел, кто платил», `get_receivers` → «Посмотрел, кому платил», `common_receivers` → «Искал общих получателей», `trace_downstream` → «Проследил деньги дальше», `cluster_summary` → «Изучил кластер»; неизвестный инструмент — показать как есть), затем ответ.
- Узлы из `highlight_gids` подсвечиваются на графе, камера показывает их через `zoomToFit(600, 80, n => set.has(n.id))`.
- Ошибка или таймаут: «Агент не ответил. Граф и роли работают без него — попробуйте переформулировать вопрос».

### Этап 5. «Изъять топ-5»
- Кнопка убирает топ-N узлов по приоритету (N выбирается: 5, 10, 20).
- В `lib/resilience.ts` считай сам: число слабосвязных компонент (union-find, направление рёбер игнорируется), размер крупнейшей компоненты, долю оборота, прошедшую через изъятые узлы (сумма `sum_kzt` рёбер, где они источник или получатель, делённая на общий оборот). Всё до и после.
- Изъятые узлы гаснут, панель показывает «до → после». Кнопка «Вернуть» всё восстанавливает.
- Цифры только вычисленные, никаких захардкоженных.

### Этап 6. Полировка
- Переключатель «Цвет: роли / кластеры».
- Подписи gid на холсте для топ-20 при приближении (`globalScale > 2`).
- Суммы в формате `1 250 000 ₸` (`toLocaleString('ru-RU')`).
- Видимый фокус клавиатуры, `prefers-reduced-motion` отключает частицы и анимацию раскрытия.

## Дизайн

Это инструмент следователя, показываемый на большом экране. Вся смелость — в самом графе, панели вокруг спокойные и строгие.

- Фон тёмно-синий, как ночная карта: `#0F1B2D`. Панели `#16263D`, границы `#24384F`, основной текст `#E6EDF5`, второстепенный `#8FA3BA`.
- Цвета ролей: консолидатор `#FF5A5F`, координатор `#C77DFF`, распределитель `#FFB547`, транзит `#4CC9F0`, конечный получатель `#57CC99`, периферия `#5C6F87`. Цвет никогда не единственный признак: в карточках и легенде рядом всегда подпись роли.
- Одна анимация-событие — раскрытие колен. Никаких появляющихся карточек, градиентов, теней и «стеклянных» эффектов.
- Числа — табличные цифры (`font-variant-numeric: tabular-nums`).
- Названия ролей по-русски: консолидатор, координатор, распределитель, транзит, конечный получатель, периферия.

## Тексты

- Все выводы — гипотезы: «признаки консолидации», «вероятный транзит». Никогда «преступник», «виновен», «организатор преступной группы».
- Не выдумывай данные, которых нет в ответе бэка: никаких имён, возрастов, городов.
- Пустые состояния и ошибки говорят, что делать дальше, а не извиняются.

## Подводные камни

- `react-force-graph` мутирует рёбра: после старта симуляции `link.source` и `link.target` становятся объектами узлов. Везде, где берёшь id, пиши `typeof l.source === 'object' ? l.source.id : l.source`.
- Соседей узла считай один раз при загрузке данных в `Map<number, {in: …, out: …}>`, а не перебором рёбер на каждый клик.
- Состояние подсветки храни в `Set<number>`, а холст перерисовывай через колбэки, а не пересозданием `graphData`.

## Сценарий демо (что должно работать безупречно)

1. Открыли страницу — видны только seed-узлы.
2. «Расследовать» — колена раскрываются, роли окрашиваются, открывается топ-20.
3. Клик по первому месту — карточка с цифрами и объяснением.
4. Жюри называет gid — поиск, наезд камеры, связи.
5. Shift+клик по нескольким seed → вопрос агенту «Кто собирает деньги с этих узлов?» → шаги, ответ, подсветка на графе.
6. «Изъять топ-5» — сеть распадается, панель «до → после».
7. Узел с обрывом — пояснение, почему он не конечный получатель.
